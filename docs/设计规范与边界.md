# 理财投资管理模块 - 设计规范

## 一、核心抽象与领域模型

**组合**是投资管理的核心边界单元。每个组合拥有独立的持仓记录和资金池，独立核算盈亏。

- **持仓**属于组合，不属于用户。同一资产可被多个组合持有，各自独立记录
- **资金池**分为主资金池（总现金）和子资金池（归属特定组合），子资金池用于组合内交易流转
- **策略**是独立的决策引擎，绑定到组合后输出交易信号，但不直接操作资金或持仓
- **自选**是用户级功能，与组合无关

## 二、职责隔离

每个模块只负责一件事，模块间通过接口通信，不直接访问彼此数据。

- 策略只输出信号，不执行交易
- 交易只执行买卖，不做收益分析
- 收益分析只读取历史数据，不修改任何状态
- 资金调拨只在投资组合模块中进行

## 三、数据所有权

谁产生数据，谁负责写入和修改。其他模块只能读取。

- 持仓数据由交易模块写入
- 资金池余额由资金调拨和交易模块共同维护
- 资产标的库独立维护，交易和持仓模块引用但不修改

## 四、安全与审计

任何资金变动必须可追溯。

- 所有资金操作（买入/卖出/调拨）必须记录操作日志
- 禁止绕过业务层直接修改数据库中的余额或持仓

## 五、一致性

系统必须始终保持以下恒等关系：

- 主资金池余额 + Σ子资金池余额 = 总现金
- 持仓份额的变更必须与资金变动在同一事务内完成

## 六、扩展性

- 新增策略类型不需要修改交易模块
- 新增持仓类型（如加密货币、房产）不需要修改收益计算逻辑
